## Deploy — READ THIS: the user can only see work that is on `main`
- **The user plays/reviews the LIVE GitHub Pages site, which is served from the `main` branch only.** Anything that is merely committed to the feature branch — or just edited in the working tree — is **invisible to the user.** "Pushed" is not enough; it must be on `main`.
- **Therefore: after ANY change the user needs to see or test, publish it to `main` in the same turn.** The flow is always: commit on the feature branch → `git push -u origin <branch>` → **fast-forward `main`** (`git push origin <branch>:main`). Do not end a turn with user-visible work stranded on the feature branch. If you're unsure whether to publish, publish.
- The site is published from `main` via GitHub Pages (classic, no workflow). After a push to `main`, GitHub Pages takes ~1–2 min to rebuild, and the user must **hard-refresh** (Cmd/Ctrl+Shift+R) to beat the CDN/browser cache. A save-`KEY` bump also clears any in-progress game (expected after a rules change).
- **This is a tabletop board game, not a web app.** Design for PRINT: if information isn't printed on a physical component, the player doesn't have it. Tooltips/hover are a design smell — they flag info with no home on a piece. In `play.html`, essential info is shown INLINE because it is printed on the tile; tooltips may carry only flavor/reminders. Every change must work as cardboard, not just on screen.

### What the game is
*Brewhouses of the Hanse* — a **2–4p** medieval-Hanseatic brewing euro (c. 1350; a 5p mode runs but isn't balance-tuned), **medium / *Great Western Trail*–*Distilled* weight** (v0.7 reeled it in from a Lacerda-grade v0.6). You run a merchant brewing house at **the Wharf** — four stations on a shared 2×2 (Market·Brewhouse·Cellar·Harbor) ringed by 8 slots — where the work runs **Source → Brew → Age → Ship.** Goods are the only currency — no money, no spendable prestige (v1.2 added **demand dice**: value-building bonuses ride a reusable d6 in a ship's berth, the pips = the ★ banked on delivery). *(Live build **v2.1.1 "Staple Rights"** (base ruleset **v1.8 "Quality Pays"**) — the v1.0 "Living Slots" keystone rebuild shipped; the live model is living-slots Buildings, four distinct kontor benefits, demand dice, 2–4p, with **value-Buildings rewarding the quality climb** (**+2★ at Q4 · +3★ at Q5**). **Three opt-in New Game toggles** ride an **expansion spine**: *Specialty Beers* (3-of-7 export draft + Blending + 3 thematic Buildings), the *Jopenbier* **Q6 capstone**, and **The Trade Roads** (Overland — a claimable Staple-Right inland network that **REPLACES the kontor majorities**). Base game byte-for-byte unchanged when all off. See `DESIGN.md` §6/§9. Lineage: v0.7 origin → v0.8 (occupancy toll, fixed-quality exports, neutral buildings) → v0.9 (tiered majorities, London = engine, seat compensation) → v0.10 (big majorities, Bergen the anchor) → **v0.11** (NEUTRAL destination-bound ships, commission, benefit-on-load) → **v0.12** (variable cask actions drawn at brew, Gruit pinned to Source, rival-loading restored) → **v0.12.3** (Hall = printed ladder, upgrades earned-only) → **v0.13** (the Flight + Masterpiece + majority cooldown) → **v0.14** (Bock un-gated — the Q5 climb reachable) → **v0.15** (the Hall goes LOCAL — Enshrine, no boat) → **v0.16/.1** (ships SAIL ONLY WHEN FULL; benefit + points seal on DELIVERY in load order; Charter gated by a SCARCE CONTRACT; vessel cap 3) → **v1.0** ("Living Slots" keystone: owned Buildings on the 8 slots, building-driven kontor value, the Floor) → **v1.1–1.8** (four kontor lanes · demand dice · the Flight · improvements moved to the Cellar · hops-led ladder Bock **2G3H** · "Quality Pays" premium) → **v1.9–v2.1** (the three expansions on the expansion spine: Specialty Beers · Jopenbier · The Trade Roads / Staple Rights) → engine polish to **KEY v84** (v82 scarce-improvement deck + face-up display of 4 · v83 repeatable Cellar Tap · v84 Cellarmaster-AI rollout tuning). Current majorities (base, off under The Trade Roads): **Bruges 4/2/0 · London 5/3/1 · Novgorod 8/5/2 · Bergen 9/5/2** (the anchor); the Hall is a printed prestige ladder **3/5/7/9**, reached by the **local Enshrine** (not a boat). `play.html` `KEY = v84`.)*

### The spine (internalize this — everything hangs off it)
- **The Wharf = four stations ringed by 8 slots; you move where the board is best (it is NOT a rondel).** Stations: **A Market (Source) · B Brewhouse (Brew) · D Cellar (Age) · C Harbor (Ship)** — the production order is Source→Brew→Age→Ship. A turn = move to an adjacent station, activate its row XOR column, resolve up to 4 stops (**slot·station·station·slot**) **in any (player-chosen) order**. Both stations fire; **stations are never closed** (no twins) — the only station cost is a **1 `G` occupancy toll** when you move onto a station a rival occupies (opening placement is free). Every base action always works; slot buildings only *add*.
- **The dual-role cask in 3 states** is the whole game in one object: **maturing** (private vessel, ages to Ready) → **on a slot** (a shared perimeter slot — your cargo-in-waiting + a **public, chunky, production-advancing action** — v0.12: DRAWN AT BREW from a 7-action pool, decoupled from quality, printed on the tile) → **delivered** (shipped to a destination → scores → gone). A cask is only ever one state; shipping converts it. **Only casks on slots are public/contestable; the brewery is private.**
- **The slots = the 8-slot perimeter ring around the stations**, a transient mix of **deployed casks · NEUTRAL ships (v0.11: destination printed, off a shuffled ship deck feeding a face-up **market of 3**; Commission places any one of the three; load YOUR OWN casks — destination benefit paid ON LOAD (goods/upgrade), points sealed ON DELIVERY; commissioning grants a free load + feeds the merchant goal; v0.12: you may load a RIVAL's cask (you pick the destination; owner scores it, you take a 1G loader bonus); a guaranteed Hulk→Bruges seeds at setup; full → sails, no fill bonus, hull returns to the deck; clock advances by marker) · 2–3 seeded neutral buildings**. **A line = its two stations + any tiles in their two slots.** **One fire rule:** on a line, the active player may use each building in its slots; cask/neutral actions are free & public and resolve **on the active player's turn** (no out-of-turn skims).
- **Value lives in *destinations*, not two tracks.** **Ship** to the **kontore** (Bruges/London/Bergen/Novgorod) for trade value + majorities (volume), or **Enshrine** at **the Hall** for prestige (scarcity — v0.15: a LOCAL Harbor action, no boat; a *deployed* Q2+ cask is withdrawn into the Hall, so it stays contestable on the slot). Both are Harbor actions, different destination — that's the volume-vs-prestige lean. **Aging** is the value-over-time signal. *(The demand market, type frontier, Fairs, route lanes, and the Hall-as-a-station are CUT.)*
- **The brewery (private) = vessels (start 2, cap 3) + a maturation track + recipes (start Gruit+Hopped; the export ladder Q3–Q5, **Bock un-gated, 2G3H** (v1.6 hops-led; un-gated since v0.14) — the Aging Cellar is a −1-step *pathway*, not a gate) + the v1.0 upgrade split: public **Buildings** (the keystone — value/transform tiles owned on the slots, earned free by delivering to **London** or bought + placed at the Market) and a few inherently-private **improvements** (Extra Vessel · Aging Cellar · Granary/Hop Garden · Harbor Crane · Lagering Cellar · Private Quay) **bought at the Cellar** (v1.7; **v82** = a scarce deck + face-up display of 4).** Deliver → author a Building → brew better → deliver better.
- **The interaction (v0.11–v0.12):** shared hulls — commissioning (with its free load) where your cargo goes, the benefit banked on delivery, filling-and-sailing to seal points, racing rivals for rich-route berths, and **loading a RIVAL's cask** (v0.12 restored this — you pick the destination, the owner scores it + benefit, you take a `1 G` loader bonus; filling a ship earns no bonus). **Scoring (v1.2; v1.8 quality premium):** kontor delivery value (a small base + the **value-Buildings** the cask shipped through — carried on a reusable **demand die**, pips = the ★ banked on delivery; **v1.8: a premium cask banks a quality premium on top — +2★ at Q4 · +3★ at Q5 — uncapping the old flat building values so the climb pays**) + tiered majorities at every kontor (**Bruges 4/2/0 · London 5/3/1 · Novgorod 8/5/2 · Bergen 9/5/2** the anchor; 2p skips 2nd) + the **Hall** fixed prestige ladder **3/5/7/9 by quality** (via the local **Enshrine**) + **the Flight** (distinct **beers** delivered, `(beers-1)²`, min 3: 3→4·4→9·5→16). *(Goals and the Masterpiece are cut — folded into the building/Flight system.)* *The win-axis is **contested kontore (volume/majority) vs the uncontested Hall (prestige/deep)**; deep stays the slightly-lower, higher-variance "stars-align" lane by design.* **End clock:** the shared **Sailed-Ships track fills** (length **6/10/13** for 2/3/4p, **+2** with The Trade Roads) → finish the round → score (any voyage advances it — a ship sailing **full**, a single-cask **Charter** (kontore-only; spend a contract + a flat `2 G` fare), *or* an **Enshrine** — the Harbor relief valves that keep the tight slots from deadlocking).
- **Terminology (canonical):** *the Wharf* = the whole core area; *stations* = the four action spaces; *slots* = the 8 perimeter spaces; a *line* = two stations + their two slots. "The Loop" / "cell" / "the wharf (as the ring)" are retired.

### Before you commit any game change, check the interlocks
1. **Theme** — does it still make medieval-brewing sense? Mechanics are dressed as brewing/trade for a reason.
2. **The Wharf & the lean** — does it keep the Source→Brew→Age→Ship flow legible, and does it shift the volume(kontore)-vs-prestige(Hall) lean? That's the heart; keep it medium-weight (interesting choices, not mental burden).
3. **Components/tiles** — does it change counts, tile families, costs, or the type/destination ladders (`COMPONENTS.md`)?
4. **All surfaces** — update `RULES.md` AND the affected docs together; then the pages. Numbers are tunable `⚙` placeholders; doc tables restate them, so a number change is a multi-file edit.
5. **`play.html` is the v2.1.1 “Staple Rights” reference implementation** (`KEY v84`; specs + `learn`/`index`/`printables`/`printables2` current). The **Charter** relief valve (`RULES.md` §5, `DESIGN.md` §21·E′/v0.16) is now gated by a **scarce contract** (start 2, Market-buy `1 G`, flat `2 G` fare — the escalating fare row retired); a single-cask **kontor** voyage that keeps the tight slots from ever deadlocking. **Ships sail only when full** (no partial early-launch), and the destination **benefit + points seal on DELIVERY**, paid in **load order**. (The **Enshrine** relief valve — a deployed Q2+ cask → the Hall, no boat — is in the prose spec too.) It also carries the **occupancy toll** (`chooseLine`: 1 `G` to move onto a rival-occupied station; opening placement free) and **balanced warm-start seeding**. After any engine change, **smoke-test headlessly** (see below) and **bump the save `KEY`**. Pace target: **~12–25 rounds** (`MAX_ROUND` ceiling ≈25; the Sailed-Ships length `SAILED_CAP` is the primary dial — note "sail full" structurally lengthens the game, so the clock is the round-count lever, not the ship rules).

### Simulating / smoke-testing the engine — `playtests/sim.js`
A reusable headless harness already exists. **Use it; don't rebuild it.** Run: `node playtests/sim.js [N]` (default `N=500`; covers **2–4p plus a 5p robustness check**, prints a per-count summary). Save each run as `playtests/sim-results-v<KEY>.txt`. **Env hooks:** `PERSONAS=1` commits each bot to a **volume/prestige/majority lean**; `CELLAR=N` marks N seats as the **deep/Q5-committed "Cellarmaster"** (the 4th pathway) — `CELLAR=1 PERSONAS=1` prints the unified **PATHWAYS report** (per-lane win-rate + score composition, the tool for "how do the strategies compare"); `SCEN=…` swaps starting-token scenarios; `TUNE=…` sweeps `DEST` re-stats without touching `play.html`.

**Strategy — drive the *canonical* engine, never a reimplementation (which would drift from `play.html`).** How it works:
- **Extract** `play.html`'s `<script>` and **append** a heuristic bot + game-runner into the **same lexical scope**, then run the combined source once in a Node `vm` with a stubbed DOM/`localStorage`. *Why append-in-scope:* the engine's `S`, `UI`, `undoStack`, `setupN` are `let`-declared → **not** exposed on the `vm` context, so you can't drive from outside; sharing scope lets the bot reach them and call `freshState`/`endTurn`/etc. directly.
- **Speed:** override `render`/`log`/`save`/`snapshot` to no-ops (they're reassignable function declarations). 1500 games run in ~3 s.
- **The bot navigates the engine's own UI state machine** — it switches on `UI.sub` (`move·line·stops·cell·brew·age·source·convert·reach·alms·goaldraw·wild·load·deploy·benefit·end` — note the literal value is still `cell` in code) and `UI.stage` (`shipdest·place·charter_cask·charter_dest`), calling the **same functions the buttons call** (`doMove`, `chooseLine`, `resolveStop`, `brewPick`, `ageAllot`, `harborLoad`, `loadOnto`, `buyTile`, `buyDisplayUp`, `benefitPick`, `endTurn`…). The bot is **topology-agnostic** (reads `CELLROLE`, not letters) and **occupancy-aware** (subtracts `cellToll` when `OCCUPANCY_TOLL` is defined). Greedy heuristics: work the Wharf, brew the highest affordable recipe, age the cask closest to Ready, deploy Ready casks, ship to the best-value *reachable* destination, build a Cog when ship-less, **earn upgrades by delivering** (no goods-buy — v0.12.3), and **Charter only as a relief valve** (slots jammed / `S.ending` / no hull & can't build).
- **Game-over detection:** loop `botActOnce()` until `S.ending && S.active===S.first && UI.sub==='end'` (gameOver fires inside `endTurn` and leaves `UI.sub==='end'`); a guard counter trips on any runaway.

**What it measures / the bar:** **0 crashes and 0 deadlocks** across 2–4p (the hard gate), rounds & % in the 12–25 band, end-trigger (clock vs `MAX_ROUND` ceiling — should be ~100% clock), winner totals/margins/ties, seat win-rate (first-player fairness), the **upgrade earned-via-ship vs bought split**, charters/game, and winner delivery-by-destination/lean.

**Strategy analysis — `playtests/sim-analyze.js`:** `TIERS=trader node playtests/sim-analyze.js 400` runs headless cohorts and reports **openings → win-rates, timing curves (first voyage/upgrade/Hall/Bergen), per-tier action profiles, destination sequencing, and win correlates**, from a structured event stream hooked on the engine's own functions (`SAVE=1` dumps raw JSONL). `TIERS=guildmaster,trader COUNTS=2` is the *oracle* cohort — what search-based play does differently (~5s/game; size N accordingly). Use it for "how is the game actually played" questions; sim.js stays the robustness gate.

**Re-run checklist after an engine change:** (1) bump the `KEY`; (2) `node playtests/sim.js 500`; (3) assert crash- & deadlock-free and pace in band; (4) commit the harness output as `sim-results-v<KEY>.txt`; (5) **also run the AI gates** — `node playtests/ai-ladder.js 600` (0 errors + every higher tier ≥60% at 2p) and `node playtests/ai-render-smoke.js` (full AI games through the *real* render layer). `play.html` carries in-page **AI seats** (Apprentice/Journeyman/Trader/**Guildmaster**/**Cellarmaster** — `AUTOMA.md`, Phases 1–3+ shipped; the Guildmaster is flat Monte Carlo (fast oracle, journeyman rollout — `GUILD_MS`); the **Cellarmaster** (v1.2) is the strong/slow deep MC — competent trader+completion-biased rollout, determinized decks, sequential halving (`CELLAR_MS`); it beats the GM ~62%. The harnesses lower both budgets for bulk runs and **shard** the GM/Cellarmaster ladder rungs — `node playtests/ai-ladder.js 600` runs the fast tiers; the slow rungs shard via `GMN`/`CMN` + `GUILD_MS`/`CELLAR_MS` envs); all in-page AI code is `ai`-prefixed so the appended sim bot never collides with it. **After a balance pass** (DEST/score retunes), also re-run the Trader weight tuner — `node playtests/ai-tune.js` (CEM over `AI_W`; ~2 min) — and adopt its verdict (copy any ADOPT weights into `AI_W`, keep the tuner's `DEFAULTS` in sync, re-run the gates).

**Known bot blind spots — read results with these in mind** (the greedy bot is not human): it value-ranks kontore so the default run under-ships Bergen & the Hall, and it charters heavily at 4p (the tight ring). These describe only the **default greedy** run. **For any strategy/lean question, run `PERSONAS=1` and/or `CELLAR=1`** (the unified PATHWAYS report) — they commit bots to the four lanes (volume/prestige/majority/deep). The current (v0.16.1) verdict: the **lanes stay balanced** — 4p ≈ vol/pres/maj/deep **25/21/32/21** (majority a touch hot; prestige/deep the low pair — cap-3 nudged deep up 19→21). **Deep stays the slightly-lower, higher-variance "stars-align" lane — by design; do NOT buff it to fair** (the greedy bot under-pilots it — under "sail full" it ships rare casks to kontore on unfillable hulls instead of enshrining; that's the GWT-shredder slot). v0.16's "ships sail full" slightly disfavors low-volume play (you need volume to fill a hull → deep leans on Enshrine/Charter), and the 2p prestige watch-item eased (~56%→~46%). The win-axis is **contested kontore vs the uncontested Hall**; the rebalance dials are the Hall prestige curve, the Enshrine throttle, or the majority cooldown (NOT Bock cost — the 3G3H probe was tested and rejected). **Lesson (v0.15): when a change alters *friction*, correct with a structure lever, not the *value* lever — and prefer a structural throttle that restores contestability over a flat fee.** The Guildmaster oracle reaches Q5 (~1/game) since Bock was un-gated. **Trust** the default greedy run for robustness/pace; use personas/cellar before any conclusion about the lean.
