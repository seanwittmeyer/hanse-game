# The Pull Framework

The retention model this skill evaluates against. Read this before reviewing.
A game's *art* gets it to the table once. None of what follows is about art —
it's about what manufactures the craving to set it up again.

This framework was built on medium-heavy euros and that's still where it's
sharpest, but the underlying question — what specifically makes someone want
to play this again — applies at any weight. What changes by weight is which
engine is doing the work and how load-bearing the legible-loss test is. Adjust
your emphasis accordingly; don't force a filler game through a depth-pull
autopsy it was never trying to pass.

## The core claim

Durable replay is generated by a **signature mechanism that produces a
recurring tension**, decisions that are **coupled or multi-use** so nothing is
throwaway, a **variability engine** for freshness, and (in games heavy enough
to have one) a **legible engine-build arc** that pays off late. Theme earns
its keep only where it is fused to mechanism rather than skinned on top — see
`theme-integration` guidance in the main skill for how to test that directly.

But "pull" is not one thing. Different games manufacture different cravings,
and which one you're building is a design decision, not an accident. There
are four systemic engines, plus one social engine that sits slightly outside
the other four because it doesn't come from the system at all.

## The four systemic pull engines

**Depth pull — legible loss + a high skill ceiling.**
You replay because you can *see why you lost* and believe you can fix it.
Built from tightly coupled / multi-use decisions, a starved economy, and a
system deep enough that good play visibly beats mediocre play. This is the
strongest and most underused retention engine in euro design, because it costs
nothing per player to maintain — no new content required. Exemplars: Lisboa
(regret at maximum density — every card coupled across 3–4 uses, every
misallocation nameable), Great Western Trail (adaptive mastery against a
co-built, moving target), Orléans (variance you author and therefore take
credit for), Agricola (forced breadth under scarcity; you always finish having
neglected something).

**Variety pull — setup variability + combo discovery.**
You replay because the puzzle is *fresh*, not because it's deep. Built from
large card pools, modular setup, drafted/drawn variability. Real and
powerful — but it puts retention on the *content roadmap*. When novelty is the
engine, expansions aren't optional, they're the business model. Exemplars:
Wingspan (hundreds of unique birds, fresh hand every game), Viticulture (the
visitor-card combo lottery — swingy, generous, sometimes near-broken on
purpose).

**Comfort pull — frictionless compounding.**
You replay because it's *absorbing and never punishes you*. Low/zero
interaction, an engine tuned to always feel like it's accelerating, sustained
low-grade satisfaction rather than spiky peaks. The pull of being absorbed,
not of being tested. Binds the solo / cozy-heavy audience hard but converts a
narrower slice. Exemplars: Unconscious Mind, the gentle side of Wingspan.

**Fantasy pull — aspirational progression you can feel.**
You replay because optimizing *is* living out a fantasy — the engine-build and
the role-fantasy are the same gesture, so the math carries emotional weight a
pure abstract can't manufacture. Converts fewer people but binds them
hardest; this is how you build a devoted niche rather than a broad hit.
Exemplar: Obsession (reputation gating literally *is* social ascent; you're
not building a machine, you're becoming respectable).

Most games are dominated by one engine and borrow a little from a second.
Naming the dominant one — and whether it's the one the designer *thinks* they
built — is the single most clarifying move in a review.

## The fifth engine, for lighter weights: social pull

You replay because of what the *table* does, not what the system does — the
laughter, the bluffing tells, the tableside drama a light ruleset exists
purely to provoke. This isn't a lesser version of the four systemic engines;
it's a different thing entirely, and it's the dominant engine for most party
and light social-deduction games. Exemplars: Codenames, Just One.

If the game under review is light enough that social pull is plausibly its
real engine, say so plainly and don't penalize it for failing a depth-pull
test it was never trying to pass. The diagnostic question shifts from "can a
player name the decision that cost them" to "does this reliably manufacture
the specific social moment it's going for, replay after replay, with new
groups" — and that's just as testable, it's just tested at the table with
different eyes than a solo design read gives you.

## The legible-loss test (load-bearing for depth-pull games)

For a game leaning on depth pull, ask: **can a player finish a game and name
the decision that cost them, and believe a cleaner line was reachable?**

- If **yes** → the game owns depth pull and will outlive its art. Losses are
  diagnosable, so improvement is felt, so players return to climb.
- If **no** → loss is *illegible*. The player can't say why they lost (this is
  Wingspan's structural ceiling — engineered never to sting, which kept the
  comfort audience but caps the depth audience and churns hardcore players
  faster). A game whose weight and marketing promise depth, but whose loss is
  illegible, is secretly running on variety pull whether or not it intended
  to — and its retention is therefore hostage to the expansion calendar.

Illegible loss in a heavy game is the most dangerous single flaw, because the
weight promises depth the game then fails to deliver: it asks for the
investment of a thinky euro and returns the diagnosability of a light one.
This test matters less as weight drops — don't run it hard against a filler
or party game; check for social pull instead (above).

## The designer's fork (apply to the game under review)

Depth and variety want *opposite* tunings:

- **Depth wants** a stable, tight, punishing, low-variance system. Coupled
  decisions, starved economy, few random swings, a high skill ceiling.
- **Variety wants** a loose, generous, modular, high-variance system. Big card
  pools, swingy combos, lots of setup permutations.

You cannot maximize both in the same subsystem. A review's job is partly to
catch a game trying to — e.g. a starved, depth-flavored core bolted to a
swingy, variety-flavored card deck that undermines the legibility the core was
building. Decide which engine each subsystem serves, and flag the ones at war
with themselves.

## How to use this in a review

1. Place the game's weight class first (see the main skill) — it tells you
   which engines are plausible candidates and how hard to run the
   legible-loss test.
2. Identify the **signature mechanism** and the **recurring tension** it
   generates. If you can't find one, that's the headline weakness at any
   weight.
3. Check that decisions are **coupled / multi-use**. Throwaway turns are dead
   weight at medium weight and up; less damning in a 20-minute filler.
4. Run the **legible-loss test** if the game is depth-weight; run the
   **social-pull test** if it's party-weight.
5. Name the **dominant pull engine** and whether it matches intent.
6. Flag subsystems whose tuning is **at war** with the intended engine.
