# Brewhouses of the Hanse — Term Registry & Style

**This file is rank 1.** Every word printed on a component comes from this registry; the
house style guide (§G) governs sentence shape. Rules: `RULES.md`. Code identifiers are not
player-facing and keep their names; only printed and rendered copy is governed here. The
pre-v8 entries (the v5 tables, the v6 and v7 families) are archived in
`archive/records/STYLE-pre-v8.md`.

## §4. The golden rule, and the laws that ride with it

1. **Rules never live in the components** — not the tiles, not the boards, not the app
   interface. Players learn rules from the rulebook and the player aid. **Component copy =
   name + trigger + effect**, nothing else: no lore, no history, no "how this fits". Boards
   carry data and slots, never paragraphs. Tooltips are one-line reminders in the same
   grammar, never a lesson.
2. **One action, one term.** An action has ONE printed name wherever it appears: the station
   face, the cask bonus, a building's line, the aid, the app. A count rides the name (*Gain 2
   goods · Age 3 · Cart 2*); a verb with no count is one of the thing (*Brew · Build · Post ·
   Raise die*). A new face never prints a second name for a standing action.
3. **Nothing prints in all caps.** An action name is Title Case wherever it names the action;
   a state is sentence case (*Ready* keeps its capital as a term; *empty · wild · vacant* do
   not); emphasis is **bold**, never capitals; a heading may set small caps by CSS, never
   `text-transform: uppercase`. The same casing on every surface: the rules master, the
   rulebook, the aid, the faces, the app's prompts, buttons and log.
4. **Icons carry the load.** The same icon for the same verb on every surface (`components.js`
   `ICON_ART`; the files in `art/ICONS.md`); a printed face never carries text an icon can say;
   goods numerals ride the goods colours (gold grain / green hops); cost before effect.
5. **A rule with no printed home yet lives in `RULES.md` only.** An in-development system
   stays out of `rulebook.html` until it leaves development.
6. **The rulebook and the components are snapshots:** no version tags, no history, no rulings.

# §G. The house style guide (the designer's standard — governs sentence shape)

**Three sources of truth, ranked:** 1. the registry above · 2. this guide · 3. `RULES.md`.
Card text never introduces a rule the rulebook does not contain. The rulebook never uses a
word the registry does not define.

Applied in this repo: §1 first principles (component text is interface; one term, one
meaning; costs before effects; icons carry load; every word costs) · §4 templating (clause
order **[Timing] [Condition] [Cost] [Effect] [Limit] [Duration]**; one effect per line; ":"
after trigger/cost; the trigger-word table; the verb lexicon; "you may" = optional, bare
imperative = mandatory) · §5 numbers (numerals always; number before icon; en-dash ranges;
true minus) · §6 canonical order + the mirror rule · §7 punctuation (serial comma; no em
dashes or semicolons in player copy; bold = registry terms, italic = flavor/reminder) · §13
banned constructions · §14 change control (term freeze before art lock; the seven proofing
passes).

For the complete general standard (localization, accessibility, component caps, QA matrix),
see the designer's style-guide document of 2026-08-02 — adopt-by-reference; any conflict
resolves in the order above.
